# Canonical Edge Logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve the approved Edge 300×300 logo and prevent asset rendering from replacing it.

**Architecture:** Store the approved PNG under `store/assets/source/`, declare its source path in the asset manifest, and copy it into the generated store-assets directory. Keep browser rendering for promo cards and screenshots. Test both dimensions and byte-for-byte source/generated equality.

**Tech Stack:** Node.js release tooling, PNG binary assets, Node.js built-in test runner.

---

### Task 1: Canonicalize and protect the Edge logo

**Files:**
- Create: `store/assets/source/edge-logo-300.png`
- Modify: `tools/release/config.js`
- Modify: `tools/release/render-assets.js`
- Modify: `test/unit/store-assets.test.js`
- Modify: `store/README.md`

- [ ] **Step 1: Write the failing asset regression**

In `test/unit/store-assets.test.js`, add an assertion that `edge-logo-300.png` has an asset-manifest source path of `store/assets/source/edge-logo-300.png` and that its generated bytes equal the bytes of that source file.

- [ ] **Step 2: Run the focused test and verify it fails**

Run: `node --test test/unit/store-assets.test.js`

Expected: FAIL because the Edge logo is currently classified as a rendered promo asset and no canonical PNG source exists.

- [ ] **Step 3: Copy the approved current PNG into the stable source location and update rendering**

Copy the current `store/assets/generated/edge-logo-300.png` byte-for-byte to `store/assets/source/edge-logo-300.png`. Add an `input` path for copy assets in `tools/release/config.js`; point the existing Chrome icon at `icons/icon128.png` and Edge logo at its new source file. Update `render-assets.js` so copy assets use their declared input path rather than a hardcoded icon path.

- [ ] **Step 4: Document the ownership rule**

In `store/README.md`, state that the Edge logo source PNG is manually maintained and `npm run assets` copies it unchanged; replacing it intentionally requires updating `store/assets/source/edge-logo-300.png`.

- [ ] **Step 5: Run focused and full release verification**

Run: `node --test test/unit/store-assets.test.js && npm run assets && npm run release:check`

Expected: PASS; generated Edge logo is exactly 300×300 and byte-identical to the canonical source, while all other store assets remain valid.

- [ ] **Step 6: Commit**

Run: `git add store/assets/source/edge-logo-300.png store/assets/generated/edge-logo-300.png tools/release/config.js tools/release/render-assets.js test/unit/store-assets.test.js store/README.md; git commit -m "fix: preserve canonical Edge store logo"`

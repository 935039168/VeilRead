# 恢复圆点、书库入口与 GitHub Pages 设计

## 目标

本次改动完成三个相互独立但共同面向首发体验的目标：

1. 自由悬浮恢复圆点使用右下角锚定坐标，浏览器窗口尺寸变化后保持用户拖动结束时距右侧、距底部的距离。
2. 设置页书库管理不再显示无法在该页面可靠执行的“打开”按钮，只保留管理操作。
3. 发布并验证 `https://935039168.github.io/VeilRead/` 及产品、隐私、支持、权利等双语页面；商店审核完成前继续显示“即将上线”。

## 一、恢复圆点右下角锚定

### 数据模型

自由悬浮窗的 `display.float.bead` 改用以下持久格式：

```js
{ right: number, bottom: number }
```

`right` 与 `bottom` 表示圆点外框距当前页面视口右边和下边的像素距离。写入前取整，并限制为能让 40px 圆点完整留在视口中的非负安全值。

默认未保存位置时使用固定右下边距。具体常量由阅读器定位函数统一提供，避免 CSS、拖动和恢复路径各自维护不同默认值。

### 旧数据兼容

旧版本保存的 `{x, y}` 继续可读。首次应用旧坐标时，阅读器依据当前视口和圆点尺寸换算为 `{right, bottom}`，立即使用换算结果定位。后续发生拖动保存时写入新格式；不要求启动时进行额外的全量迁移写入。

兼容读取只接受有限数值。损坏、越界或缺失数据回退到默认右下位置。

### 定位和窗口变化

阅读器内部只保留规范化后的右下锚点。显示圆点时，由当前视口计算：

```text
left = viewportWidth - beadWidth - right
top  = viewportHeight - beadHeight - bottom
```

计算结果必须被限制在安全可见范围。窗口 `resize` 后，如果圆点当前显示或已有保存锚点，重新调用同一定位函数，因此不会把右下锚点误当成旧的绝对坐标。

拖动过程中仍使用 `left/top` 提供即时视觉反馈；拖动结束时把最终矩形转换为 `right/bottom`，保存到设置，并更新内存锚点。

悬浮阅读窗移动、缩放或重置后，继续沿用现有“圆点重新跟随窗体”的行为：清除用户圆点锚点，下一次收起时根据窗体和吸附边计算圆点位置。用户再次拖动圆点后，新锚点重新成为后续窗口缩放的依据。

## 二、设置页书库管理

设置页无法直接承载页面阅读层，因此书库列表不再创建“打开”按钮，也不再保留其标签页查询、消息发送和错误弹窗代码。

设置页继续提供：

- 导入 TXT；
- 添加及编辑在线书信息；
- 显示阅读进度；
- 重置进度；
- 删除书籍。

popup、普通网页阅读层和浏览器原生侧边栏的打开、续读、翻章能力不变。README、手工验收和测试必须明确：设置页负责管理，实际阅读从 popup、网页阅读层或原生侧边栏进入。

## 三、GitHub Pages 官网

### 页面范围

复用并完善仓库现有 `site/` 静态站点，保持紫色视觉和双语导航。正式部署必须提供：

- `/VeilRead/`：按浏览器语言跳转，并提供手动语言入口；
- `/VeilRead/zh-CN/`：中文产品主页；
- `/VeilRead/en/`：英文产品主页；
- `/VeilRead/privacy/zh-CN/` 与 `/VeilRead/privacy/en/`：双语隐私政策；
- `/VeilRead/support/zh-CN/` 与 `/VeilRead/support/en/`：双语支持页；
- `/VeilRead/rights/`：双语权利声明。

所有页面必须互相可达，保留 GitHub Issues 支持入口，并与仓库的“保留全部权利、公开源码仅供查看”政策一致。

### 商店入口

中文和英文产品主页继续显示 Chrome 与 Edge“即将上线 / Coming soon”。在两家商店审核通过并取得正式地址前，不添加临时下载、Release ZIP 或不可验证的商店链接。

### 部署

当前线上 404 的原因是仓库没有启用 GitHub Pages，`actions/configure-pages` 因找不到 Pages site 而失败。工作流改为允许 `configure-pages` 为仓库启用 Pages，并继续通过 GitHub Actions 上传 `site/` 目录和部署 Pages artifact。

推送后检查 Pages 工作流结论，并逐一请求所有正式 URL。只有 HTTP 成功、语言跳转和页面内容检查通过后，才把官网发布标记为完成。

## 四、错误处理与边界

- 圆点坐标只处理有限数值；异常值回退默认位置。
- 小窗口下优先保证圆点完整可见，允许实际边距小于保存边距；窗口恢复后重新按保存锚点计算。
- 旧 `{x, y}` 仅用于兼容读取，新写入统一使用 `{right, bottom}`。
- 设置页删除“打开”入口不改变书籍和进度数据结构。
- GitHub Pages 部署失败时保留工作流日志，不把本地静态检查当作线上成功。
- 浏览器商店地址为空时只显示状态文本，不渲染空链接。

## 五、测试与验收

采用测试驱动方式覆盖：

1. 默认圆点位于右下角。
2. 拖动保存 `right/bottom`，不再写入 `x/y`。
3. 视口变化后保持右、下边距。
4. 小视口时坐标被安全限制，恢复大视口后仍依据原锚点。
5. 旧 `{x, y}` 可换算并正确显示。
6. 设置页书库列表不生成“打开”按钮和相关打开消息。
7. README 与手工验收不再要求从设置页打开书籍。
8. 站点文件、双语互链、Issues 地址、“即将上线”状态和 Pages 工作流启用参数均通过自动审计。

完成后运行完整单元测试、语法检查、发布审计、打包与 ZIP 内容校验。推送后验证 GitHub Pages 工作流和所有正式 URL。

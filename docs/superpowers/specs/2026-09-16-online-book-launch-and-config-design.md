# 在线书启动与配置设计

**目标：** 让用户可以在设置中心维护在线书的书名、起始章节链接和目录/书籍链接；从 popup 或设置中心打开书库中的在线书时，跨站点也能可靠启动，同时保留同站点原页打开的低干扰体验。

## 根因

在线书的启动消息最终由当前标签页的内容脚本处理。该脚本用 `validateReadableUrl(target, location.href)` 限制章节 URL 必须与当前标签页同源。popup 不论内容脚本返回的是跨站点拒绝、超时、HTTP 状态还是正文识别失败，都会显示同一条“请确认已联网且在普通网页上”的笼统提示。因此，在任意普通网页上从书库打开另一个站点的在线书会稳定失败，刷新当前页不会改变这个条件。

## 方案

### 启动路径

1. popup 和设置中心继续通过统一的 `tabSend` 入口请求打开在线书。
2. 后台比较目标章节与当前标签页的来源：同源时保持当前行为，在当前页抓取章节并显示阅读层，不破坏用户正在浏览的页面。
3. 跨站点时后台新开并激活目标章节页，将一次性“待打开在线书”任务写入 `chrome.storage.session`。目标页加载完成后，后台向其内容脚本发送启动消息；内容脚本直接提取当前文档，而非再次跨页请求。
4. 待启动任务消费后立即删除。失败时内容脚本显示具体、可操作的错误；同源路径的 popup / 设置中心也直接展示后台返回的实际错误信息。

### 数据与配置

在线书仍以目录/书籍链接作为稳定身份 `bookUrl`，章节进度仍以章节 URL 保存。设置中心的书库管理新增“添加在线书”表单，并为每本在线书提供内联“编辑关键信息”表单：

- 书名：为空时用目标站点域名作为默认名；启动消息优先使用配置的书名，避免网页标题覆盖用户命名。
- 起始章节链接：打开书库时使用的章节地址。
- 目录/书籍链接：用于书库身份与目录关联；可与章节链接不同。

保存时仅允许 HTTP(S) URL。修改目录/书籍链接即修改书籍身份：先创建/更新新记录，再清理旧元数据与旧进度，界面明确要求确认该动作。只改书名或章节链接不会删除现有书籍身份。

### 失败提示与安全

自动翻章与目录抓取继续严格限制为阅读页同源，以保留登录 Cookie 与隐私边界。跨站点启动不在扩展后台抓取网页，而是导航到用户明确配置的目标页面后，由该页面的内容脚本解析，因此不会扩大数据访问范围。错误提示将区分内部页/注入失败、页面不可访问、HTTP 错误、超时和未识别正文。

### 测试

新增纯函数测试覆盖在线书配置 URL 标准化和来源比较；为后台任务与 popup 错误透传添加可测试辅助函数。手工验收覆盖同源不跳转、跨站新标签自动打开、配置新增/编辑、错误提示和会话任务清理。
